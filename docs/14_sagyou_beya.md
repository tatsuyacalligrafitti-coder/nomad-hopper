# 作業部屋（2つのセッションを同時に動かす）

2026-08-16 設置。

## なぜ要るのか

2026-08-15、同じフォルダで2つのセッションを同時に動かしたところ、
片方のコミットがもう片方のブランチに載った。PRの中身が空だったことで
気づけたが、気づかなければ無関係なコードが混ざったままマージされていた。

原因は **1つのフォルダは、同時に1つのブランチしか開けない** こと。
2つのセッションが同じフォルダを取り合うと、後から切り替えたほうが勝つ。
そこで、セッションごとにフォルダを分ける。

## 部屋の置き場所と名前

| 部屋 | フォルダ | 使いかた |
|---|---|---|
| 1つ目 | `~/nomad-hopper` | もとからあるフォルダ。**場所も名前も変えない** |
| 2つ目 | `~/nomad-hopper-b` | 必要なときに作り、終わったら片づける |
| 3つ目 | `~/nomad-hopper-c` | 同上 |
| 4つ目 | `~/nomad-hopper-d` | 同上 |

命名規則は **`nomad-hopper-` のうしろに b / c / d** を付けるだけ。
ブランチ名はフォルダ名に入れない。部屋の中で開くブランチは入れ替わるため、
名前に入れると、名前と中身がすぐ食い違う。

履歴（コミット・ブランチ）は1つのまま共有される。増えるのはフォルダだけ。

## 使いかた

道具は `~/ai-office/heya.sh` にある。
nomad-hopper の中には置かない。中に置くと、その道具を持たないブランチに
切り替えた瞬間に道具ごと消えるため。

### いまの部屋を見る

**ターミナルに貼ってください:**

```bash
cd ~/ai-office && ./heya.sh
```

どのフォルダでどのブランチが開いているかが並ぶ。

### 2つ目の部屋を用意する

**ターミナルに貼ってください（`feat/なにか` の部分は好きなブランチ名に）:**

```bash
cd ~/ai-office && ./heya.sh --new feat/なにか
```

空いている部屋を1つ選び、そのブランチを開く。
指定した名前のブランチが無ければ、main から新しく作る。
最後に「この部屋を使うには」として `cd ... && claude` の1行が表示されるので、
**新しいターミナルの窓を開いて**、その1行を貼る。これで2つ目のセッションになる。

道具が自動でやること:
- 履歴を最新にする
- そのブランチが別の部屋で開いていたら、止める（取り合いを防ぐ）
- 許可の設定・試作画面の設定・`.env.local` を、もとの部屋から写す
- 部品（npm install）を入れる
- 新しいブランチの送信先が main にならないようにする

### 使い終わった部屋を片づける

**ターミナルに貼ってください:**

```bash
cd ~/ai-office && ./heya.sh --close b
```

`b` のところは片づけたい部屋の名前。フォルダが消えるだけで、
**ブランチと履歴は残る**。

保存していない変更や、GitHubへ送っていないコミットが残っていると、
道具が中身を並べたうえで **片づけを断る**。捨てないための仕組み。
その場合は先にコミットして送信するか、内容を見たうえでもう一度実行する。

## 気をつけること

- **同じブランチを2つの部屋で同時に開くことはできない**。git が断る。
  これは制限ではなく、2026-08-15 の事故を起こさないための性質。
- 部屋ごとに部品（node_modules）と試作画面の番号は別。
  試作画面は空いている番号を自動で選ぶ設定になっている。

## 実測で確かめたこと（2026-08-16）

- 片方の部屋でブランチを切り替えても、もう片方は変わらない（両方向で確認）
- 同じブランチを2つの部屋で開こうとすると git が断る
- 追加した部屋でも、危険な操作の見張り（guard.sh）が効く。
  見張りは `~/.claude/hooks/guard.sh` にあり、フォルダに関係なく働く
- 見張りが誤って普通の操作を止めることはない（送信・コミット・ビルド・
  部品入れ・後片づけ・部屋の増減で確認）

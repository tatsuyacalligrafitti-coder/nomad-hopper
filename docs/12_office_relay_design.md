### 判明した構造的な事実（設計の前提）

1. **web版Claude（claude.ai）はローカルのファイルもシェルも触れない。** これは設定で変えられない。
   web版を使い続ける限り、web版が出した文字列は必ず誰かが運ぶ必要がある。
2. **Claude Code はローカルを触れる。** 台帳追記もナレッジ生成も、Claude Code なら自分で実行できる。
   つまり伝書鳩が発生するのは「web版で決めて、Claude Code で実行する」という**役割分割そのもの**が原因。
3. **`decisions_all.md` の生成は既に自動。** 壊れているのは「web版のナレッジ欄に人が入れ直す」1手だけ。
   ここは技術的に自動化できない（web版のナレッジはアップロード式で、外部から差し替える経路がない）。
   → **自動化ではなく、差し替えを不要にする方向でしか解けない。**
4. **`add_decision.sh` は現在のブランチにコミットする。** 自動化するとき、作業ブランチにいると
   決定行がそのブランチに閉じ込められ、マージし忘れると台帳から消える。**この穴は先に塞ぐ必要がある。**

## 2. 提案A — 台帳追記の「保留箱」方式（問題1のうち台帳部分）

### 何をするのか
AI（Claude Code）が「これは決定として残すべき」と判断したとき、台帳に直接書かず、
**保留箱**という待機用のファイルに積むだけにする。ウエマツはコマンドを1つ叩くと、
待機中の決定文が1件ずつ日本語で表示され、「入れる／入れない／文言を直す」を選べる。
選んだものだけが台帳に入る。

### これで何が起きるか
ウエマツがターミナルに1行ずつ貼る作業がなくなる。世に出るものは変わらない（台帳はローカル、
本番サイトには一切影響しない）。**「何が記録されるかを事前に見て止める」判断は残る** —
むしろ、いま貼る前に読んでいるのと同じものを、まとめて読む形になる。

### やらなかったらどうなるか
決定のたびにウエマツが1行を運び続ける。運ぶのが面倒で記録を省いた決定は台帳に載らず、
次のセッションが誤った前提で作業する。

### 誰が何を失うか
- **ウエマツが失うもの**: 「1行ずつその場で貼る」という細かい確認のリズム。代わりに
  「まとめて見て選ぶ」に変わる。**溜めたまま忘れると、決定が台帳に入らない期間ができる**
  （対策: ダッシュボードの決裁箱に「保留中の決定 N件」を常時表示する）
- **AIが失うもの**: なし
- **不可逆な影響**: なし。保留箱は台帳とは別ファイルで、承認しない限り台帳は変わらない

### 付随して直すもの（提案Aを採る場合は必須）
`add_decision.sh` が作業ブランチにコミットしてしまう穴を塞ぐ。
案A-1: 台帳の追記だけは常に main で行う（追記前に main に切り替え、終わったら戻す）
案A-2: コミットせず作業ツリーに残し、ウエマツが見えるところで止める
→ **A-1を推奨**。台帳の正本は1本であるべきで、ブランチごとに違う台帳があるほうが危険。

## 3. 提案B — 指示の受け渡し（問題1のうち設計指示の運搬）

### B-1（推奨）: 設計もClaude Code側で行い、web版の役割を縮小する

#### 何をするのか
コードや仕組みに繋がる話（設計・実装指示・台帳の決定）は、最初から Claude Code のセッションで行う。
web版の本社チャットは「コードに触らない相談」——方針、優先順位、体制の話——だけに絞る。

#### これで何が起きるか
設計した人と実装する人が同じになるので、運ぶものが無くなる。コピペはゼロになる。
本番に出るかどうかは変わらない（今まで通り、ウエマツがGitHubでマージしたときだけ出る）。

#### やらなかったらどうなるか
web版が長い設計を出すたびに、ウエマツが数十回運ぶ。運ぶ途中で抜けた指示が事故になる
（今日の混乱と同じ構造）。

#### 誰が何を失うか
- **ウエマツが失うもの**: **スマホから設計相談ができなくなる**（Claude Code はMacの前でしか使えない）。
  web版の読みやすい画面と、プロジェクトのナレッジ検索。長文の設計議論をチャット履歴として
  web版に残せなくなる（代わりに `docs/` にファイルとして残る）
- **AIが失うもの**: web版のプロジェクトナレッジ（両課横断の記憶）。ただし Claude Code は
  正本の台帳を直接読めるので、実質的な損失は小さい
- **不可逆な影響**: なし。いつでもweb版に戻せる

### B-2: 依頼箱（`requests/`）方式 — 中間案

#### 何をするのか
web版が出した指示を、ウエマツが**1回だけ**ファイルに保存する（`~/ai-office/requests/` に置く）。
Claude Code は起動時にその箱を見て、中身を読んで実行する。

#### これで何が起きるか
1つの依頼につき数十回だった運搬が、1回に減る。web版は今まで通り使える。

#### やらなかったらどうなるか
提案B-1を採らない限り、運搬は数十回のまま。

#### 誰が何を失うか
- **ウエマツが失うもの**: ほぼ無い。ただし**運搬はゼロにならない**（1回は必ず残る）。
  「ファイルに保存する」という新しい操作を1つ覚える
- **AIが失うもの**: なし
- **不可逆な影響**: なし

### B-3: 本社を Claude Desktop に移し、ローカルを読ませる

#### 何をするのか
Claude Desktop に「ファイルを読む道具」を**読み取り専用で**繋ぎ、本社チャットを Desktop で行う。
Desktop は正本の台帳を直接読めるようになる。

#### これで何が起きるか
本社が常に最新の正本を見るようになり、**ナレッジの差し替えが不要になる**（問題2が消える）。
ただし Desktop はコマンドを実行できないので、**指示の運搬は残る**。

#### やらなかったらどうなるか
本社は控えの台帳しか読めず、差し替えを忘れると古い前提で判断する。

#### 誰が何を失うか
- **ウエマツが失うもの**: スマホからの本社会議（Desktopは Mac のみ）。
  **設定変更の作業が1回発生する**（Desktop の設定ファイルを書き換える）
- **AIが失うもの**: なし
- **不可逆な影響**: **注意すべき点がある。guard.sh は Claude Code 専用の安全装置で、
  Claude Desktop には効かない。** Desktop に書き込み権限を与えると、guard.sh の外側で
  ファイルを書き換えられる状態になる。**読み取り専用に限定することが絶対条件**。
  書き込みを許すなら、この案は採るべきでない

## 4. 提案C — ナレッジ差し替えの無害化（問題2）

**前提**: web版のナレッジ欄に外部から差し替える経路は存在しない。**自動化はできない。**
できるのは「忘れても壊れない形にする」ことだけ。

### C-1（推奨）: ナレッジから台帳の中身を消す

#### 何をするのか
web版のナレッジに置くのを、決定台帳の全文（`decisions_all.md`）ではなく、
**「台帳の中身はここには無い。判断する前に必ず正本を取り寄せること。正本は各課の
docs/10_decisions.md」という1枚の紙**に差し替える。中身そのものを置かない。

#### これで何が起きるか
古い台帳が存在しなくなるので、**古い台帳を根拠に誤判断する事故が構造的に起きなくなる**。
差し替えを忘れても壊れない（差し替えるものが無い）。

#### やらなかったらどうなるか
今日と同じ事故が繰り返される。差し替えは人の記憶に依存し、記憶は必ず抜ける。

#### 誰が何を失うか
- **ウエマツが失うもの**: 差し替え作業そのもの（これは得るもの）。
  代わりに、**本社に判断させるときは毎回、台帳を渡すか Claude Code に聞く手間が増える**
- **AIが失うもの**: web版が台帳を自分で検索する能力。**本社の初動が1手遅くなる**
- **不可逆な影響**: なし。元に戻せる

### C-2: 控えに「賞味期限」を書く（最小の手当て）

#### 何をするのか
`decisions_all.md` の冒頭に、生成日時に加えて
**「この控えは○月○日時点。今日の日付と3日以上離れていたら古い。判断の前に正本を確認せよ」**
という指示文を自動で埋め込む。web版Claude が自分で古さに気づける形にする。

#### これで何が起きるか
差し替えを忘れても、本社が「これは古い」と自己申告するようになる。中身は残るので検索は効く。

#### やらなかったらどうなるか
控えの古さは誰にも見えないまま、確定事項として使われる。

#### 誰が何を失うか
- **ウエマツが失うもの**: なし
- **AIが失うもの**: なし
- **不可逆な影響**: なし
- **弱点**: **AIが指示文を読み飛ばせば効かない。** C-1のような構造的な保証はない。
  「気づける」だけで「防げる」わけではない

### C-3: 差し替えのリマインドを出す（最も弱い）
差し替えから何日経ったかをダッシュボードに出すだけ。人の記憶に依存する点は変わらない。
**推奨しない**（今日の事故は「忘れた」ことが原因であり、忘れないよう促す仕組みは同じ失敗を繰り返す）。

## 5. 推奨の組み合わせ

| 問題 | 推奨案 | 理由 |
|---|---|---|
| 台帳追記の運搬 | **A（保留箱）** ＋ ブランチ穴の修正(A-1) | 運搬ゼロ・判断は残る。要件に完全一致 |
| 指示の運搬 | **B-1（設計もClaude Code側）**。移行が重いなら **B-2（依頼箱）** から | B-1だけが運搬をゼロにできる。B-2は半分 |
| ナレッジ差し替え | **C-1（中身を置かない）** | 忘れても壊れない唯一の形。C-2は気休め |

**B-3（Desktop本社）は単独では推奨しない。** ナレッジ問題は解けるが指示の運搬は残り、
一方で guard.sh の効かない領域を新設することになる。C-1 のほうが安く同じ効果を得られる。

### 守られること（3案すべてに共通）
- **guard.sh は一切触らない。** ブロックパターンの追加も削除もしない
- **ウエマツの判断は減らない。** 成果物のOK・GitHubでのマージは今まで通り。
  台帳に何を記録するかの判断も残る（形が「貼る」から「選ぶ」に変わるだけ）
- **減るのは運搬だけ**
